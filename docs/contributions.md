# 个人贡献与协作边界

这个作品集将可以直接检查的公开实现，与原系统的职责自述分开记录。原说明中的“全流程负责”表示参与范围，不能据此推定每个模块均由个人独立完成。

| 类型 | 具体工作 | 当前依据与边界 |
| --- | --- | --- |
| 独立实现：本公开示例 | 证据范围过滤与加权、评价状态展示、合成输入到JSON及终端显示的生成、行为测试与内容检查 | 可直接阅读并运行本仓库代码；为公开展示独立编写，没有复制生产实现 |
| 主要维护：原系统 | 需求与产品流程、Step1/Step2 接口、任务与报告链路、前端评价状态及历史兼容、回归与部署排查 | 既有项目文档将这些列为本人职责；各模块的独立实现、主要维护或共同开发比例尚未逐项核实 |
| 团队协作：原系统 | 核心生产代码被合作团队用于尚在内测的产品 | 当前作品集不据此认领合作团队的产品化、上线、用户增长或后续开发成果；具体共同开发分工待确认 |
| 外部能力 | ASR、语言模型、React、FastAPI 等框架与依赖 | 集成、适配和维护不等于原创这些技术；生产代码和素材的公开权另行确认 |

可从以下入口核验本仓库的工程判断：

- [证据与评分一致性](case-studies/evidence-aware-scoring.md)：缺失、可靠零值与部分可评价如何影响计算和显示。
- [公开闭环说明](../examples/README.md)：从合成输入到JSON及显示结果的复现命令。
- [验证记录](validation.md)：公开示例测试与原系统历史记录分别列示。

## 待本人核实后再用于简历的细分

1. 需求、预处理、分析、后端、前端和部署各模块分别属于独立实现、主要维护还是团队协作；对应时间段、提交或可公开证明是什么。
2. 合作团队负责哪些核心实现、产品化工作和后续维护；个人可公开描述的范围是什么。
3. 生产代码、历史分析包、截图、报告、课堂音视频是否具备公开或再许可授权；是否需要共同开发者或业务方确认。

当前可使用的表述是“参与并维护课堂视频分析平台，公开提供独立编写的工程示例”。在上述分工得到确认前，不使用“独立完成整套平台”“全部核心算法原创”或已商业上线等表述。
