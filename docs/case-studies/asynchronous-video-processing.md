# 案例：异步视频处理

## 背景与流程

视频预处理、ASR 和分析的耗时超过普通页面操作。页面需要能查询阶段、离开后查看历史，并在取消或失败时知道处理停在哪一步。

既有原系统说明将流程分为：接收任务 → 预处理 → 输入校验 → 分析 → 交付。任务状态与产物索引持久化，Worker 执行阶段工作，前端读取状态和结果。取消与失败保留阶段信息，任务目录、并发和所有权由后端管理。

## 关键判断

| 判断 | 解决的问题 |
| --- | --- |
| 将任务与页面连接分开 | 页面关闭不应成为唯一的任务状态记录 |
| 显示阶段与终态 | “已接收”“分析完成”“交付失败”有不同含义，不能只显示一个完成百分比 |
| 分别表达执行状态与评价范围 | 任务执行完成不等于每个指标都有足够证据；报告仍可包含待确认项 |
| 取消与失败保留上下文 | 后续定位需要知道阶段及产物位置，不能仅返回笼统失败文字 |

这些是既有维护材料中的设计边界。这里不提供生产 Worker，也没有用假上传、假进度条或静态报告模拟实时模型调用。

## 验证与取舍

[历史记录](../validation.md)列出原系统当时的回归与交付检查，本次公开示例只运行证据聚合与展示闭环。它不验证异步服务、取消竞态、跨进程恢复或并发任务隔离，也不据此声明 exactly-once、分布式高可用或 SLA。

查看者可以从[架构图](../architecture.md)理解原系统流程，再从[证据案例](evidence-aware-scoring.md)直接运行“任务完成与指标可评价不同”的报告侧示例。生产故障的详细原因和修复效果需要对应记录后才能补充，不在此编造案例。
