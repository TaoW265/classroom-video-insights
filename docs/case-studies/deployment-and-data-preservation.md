# 部署与数据保全

## 问题

仓库版本与实际运行来源可能不同；存储可读也不等于运行账号可写。迁移需要同时保留任务历史与报告，才能确认服务和数据都已恢复。

## 原因

代码提交、进程工作目录、解释器、预处理路径和数据卷是不同的运行要素。仅检查进程存活，无法确认代码来源或迁移完整性。

## 处理

1. 确认活动和排队任务，备份代码身份、配置、数据库及历史产物后停服。
2. 核对实际工作目录、Step1路径和解释器、Step2提交及前端代理。
3. 验证运行账号的写权限；共享存储受限时转存至可写本地盘，保留原件和容器引用关系。
4. 恢复后检查任务状态、已登记报告哈希与结果接口；回滚时同时匹配代码和数据路径。

这些检查分别回答“运行了哪份代码”“数据能否写入”“历史内容是否保留”“结果能否被读取”。私有配置独立存放，避免与可公开代码混合。

## 验证

[历史记录](../validation.md)保留迁移时的状态、报告哈希和接口检查摘要，说明一次迁移中的核对方法。它不覆盖全故障演练、自动备份体系或可用性承诺。
